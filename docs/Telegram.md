# Telegram

VoidAuth может отправлять сообщения пользователям через Telegram-бота: ссылки сброса пароля, уведомление об одобрении аккаунта и уведомления администраторам. Telegram также можно использовать для подтверждения аккаунта вместо почты или вместе с ней.

Telegram работает **в дополнение** к email и не требует настройки SMTP.

## Как это устроено

- Бот сам не может написать человеку по username. Поэтому пользователь привязывает Telegram сам: открывает в VoidAuth одноразовую ссылку вида `https://t.me/<бот>?start=<код>` и нажимает в Telegram **Start**.
- Бот получает сообщение `/start <код>`, находит по коду пользователя и запоминает его чат. После этого бот может писать этому пользователю.
- Ссылка действует **30 минут** и работает один раз. Новая ссылка отменяет предыдущую.
- У пользователя может быть привязан только один Telegram-аккаунт. Один Telegram-аккаунт нельзя привязать к двум пользователям.
- Бот получает сообщения через long polling (`getUpdates`). Webhook и входящий доступ из интернета к серверу не нужны: достаточно исходящего доступа к `https://api.telegram.org`.

## Настройка

### 1. Создайте бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Укажите имя и username бота (username должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AA...`. Это секрет: с ним можно управлять ботом.

По желанию там же задайте описание (`/setdescription`) и аватар (`/setuserpic`). Пользователи видят описание до нажатия Start.

### 2. Передайте токен в VoidAuth

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | | Токен бота от BotFather. Без него Telegram выключен, и кнопки Telegram в интерфейсе не показываются. |
| `TELEGRAM_RETRY_COUNT` | `5` | Сколько раз повторять отправку сообщения при сетевой ошибке, ответе 429 (слишком много запросов) или 5xx от Telegram. `0` — без повторов. Полезно, если доступ к Telegram нестабилен. |
| `CONTACT_VERIFICATION` | как `EMAIL_VERIFICATION` | Какими контактами пользователь может подтвердить аккаунт. Подробнее ниже. |

Пример для `docker compose`:

```yaml
services:
  voidauth:
    image: git.luklu.com/pub/voidauth:contacts
    environment:
      APP_URL: https://auth.example.com
      STORAGE_KEY: ...
      DB_PASSWORD: ...
      TELEGRAM_BOT_TOKEN: 123456789:AA...
      CONTACT_VERIFICATION: telegram
```

### 3. Проверьте запуск

В логах при старте должна появиться строка:

```
Telegram bot connected as @<username бота>.
```

Возможные ошибки в логах:

| Сообщение | Что значит |
| --- | --- |
| `Telegram bot token was rejected, check TELEGRAM_BOT_TOKEN. Telegram is disabled.` | Неверный или отозванный токен. Telegram выключается до перезапуска. |
| `Telegram polling conflict, the bot has a webhook set or is used by another running instance.` | Этот же токен использует другой процесс (второй экземпляр VoidAuth или другая программа) или у бота включён webhook. На один токен — один запущенный VoidAuth. Webhook снимается запросом `https://api.telegram.org/bot<токен>/deleteWebhook`. |
| `Telegram polling failed.` | Нет связи с Telegram. VoidAuth повторяет попытку каждые 15 секунд. |

## Подтверждение аккаунта: `CONTACT_VERIFICATION`

`CONTACT_VERIFICATION` задаёт список типов контактов, которыми можно подтвердить аккаунт. Аккаунт считается подтверждённым, если подтверждён **хотя бы один** контакт из списка.

| Значение | Поведение |
| --- | --- |
| не задано | Как в оригинальном VoidAuth: работает `EMAIL_VERIFICATION` (по умолчанию включено, если задан `SMTP_HOST`). |
| `telegram` | Нужно привязать Telegram. Email при регистрации необязателен. |
| `email` | Нужно подтвердить email, как при `EMAIL_VERIFICATION=true`. Email при регистрации обязателен. |
| `email,telegram` | Хватает любого из двух. Email при регистрации необязателен. |
| `true` | Все настроенные типы: `email`, если задан `SMTP_HOST`, и `telegram`, если задан `TELEGRAM_BOT_TOKEN`. |
| `false` | Подтверждение не требуется. Telegram всё равно можно привязать для уведомлений. |

Если `CONTACT_VERIFICATION` задан, `EMAIL_VERIFICATION` игнорируется. Неизвестный тип в списке останавливает запуск. Если указан тип, который не настроен (например, `telegram` без токена), в логе будет ошибка: пользователи не смогут подтвердить аккаунт.

На администраторов требование подтверждения не распространяется.

Пока аккаунт не подтверждён, пользователь не может войти в приложения и не виден в LDAP.

## Что видит пользователь

### Привязка Telegram

**При регистрации или входе**, если аккаунт ещё не подтверждён, открывается страница подтверждения:

1. Пользователь нажимает **Link Telegram**, затем **Open Telegram**.
2. В Telegram открывается бот, пользователь нажимает **Start**.
3. Бот отвечает «Your Telegram account is now linked…». Страница VoidAuth сама замечает привязку в течение нескольких секунд и продолжает вход.

Если ссылка устарела, бот ответит «This link is invalid or has expired». В этом случае нужно нажать кнопку ещё раз и получить новую ссылку.

**В профиле**, в блоке **Contacts**, можно привязать Telegram, открыть бота и отвязать Telegram. Последний контакт, которым подтверждён аккаунт, отвязать нельзя, иначе пользователь потеряет доступ. Сначала нужно подтвердить другой контакт.

Привязать или отвязать Telegram можно с теми же правами, что и сменить email. Если включена MFA, может потребоваться повторный вход с нужными факторами.

Если написать боту что-то кроме ссылки привязки, он ответит, что нужно открыть ссылку из профиля.

### Сброс пароля

На странице **Forgot Password** пользователь вводит username или email. Ссылка сброса придёт на подтверждённый email (если настроен SMTP) и во все привязанные мессенджеры. Страница доступна, если настроен email или Telegram.

### Уведомления

Бот отправляет:

- **ссылку сброса пароля** — по запросу пользователя или когда администратор нажимает **Send** на странице **Password Resets**;
- **сообщение об одобрении аккаунта**, если включён `SIGNUP_REQUIRES_APPROVAL`, — один раз, когда администратор одобряет пользователя;
- **уведомление администраторам** о пользователях, ожидающих одобрения, — администраторам с привязанным Telegram. Частота задаётся той же переменной `ADMIN_EMAILS`, что и для писем (по умолчанию не чаще раза в час, `false` выключает).

Отправленные сообщения записываются в таблицу `contact_log`, аналог `email_log`. В интерфейсе этот журнал не показывается.

## Для администратора

- **Приглашения.** На странице приглашения есть кнопка **Share via Telegram**: она открывает окно «Поделиться» в Telegram со ссылкой-приглашением. Бот для этого не нужен, ссылку можно отправить в любой чат. Без SMTP кнопка отправки приглашения по почте скрыта.
- **Карточка пользователя.** Отметка **Telegram Linked** показывает, привязан ли Telegram. Отметка **Email Verified** и одноимённая колонка в списке пользователей видны, только если email настроен.
- **Пункт меню Sent Mail** виден, только если настроен SMTP.

## Ограничения и советы

- Бот работает только в личных чатах. Сообщения из групп и каналов игнорируются.
- Если пользователь заблокировал бота, сообщения ему не доставляются. Повторно они не отправляются, ошибка пишется в лог.
- Если Telegram в вашей сети работает нестабильно, увеличьте `TELEGRAM_RETRY_COUNT`. Повторы задерживают ответ на запрос, например на сброс пароля, пока сообщение не будет отправлено или попытки не закончатся.
- Текст сообщений бота пока только на английском.
- Токен бота не выводится в логи и сообщения об ошибках. Если он всё же утёк, отзовите его в BotFather (`/revoke`) и задайте новый в `TELEGRAM_BOT_TOKEN`.
